# WebQuiz

Веб-приложение для проведения интерактивных викторин в реальном времени.

WebQuiz позволяет организатору создавать викторины, управлять вопросами и запускать игровые сессии. Участники подключаются к сессии по коду комнаты, отвечают на вопросы в установленное время и получают итоговый результат.

## Возможности

### Организатор

- регистрация и авторизация;
- создание, редактирование и удаление викторин;
- выбор категории викторины;
- добавление, редактирование и удаление вопросов;
- настройка вариантов ответов;
- поддержка вопросов с одним или несколькими правильными ответами;
- добавление изображений к вопросам;
- настройка времени на вопрос;
- создание и запуск игровой сессии;
- завершение игры и просмотр результатов участников;
- просмотр истории проведённых игр.

### Участник

- регистрация и авторизация;
- подключение к игровой сессии по коду комнаты;
- получение вопросов в реальном времени;
- отправка одного или нескольких вариантов ответа в течение установленного времени;
- просмотр результатов и итогового рейтинга;
- просмотр истории завершённых игр.

### Игровая логика

- передача игровых событий через WebSocket;
- таймер для каждого вопроса;
- проверка ответов на стороне сервера;
- подсчёт баллов и формирование результатов;
- поддержка вопросов с одним и несколькими правильными ответами;
- поддержка изображений в вопросах;
- сохранение результатов в PostgreSQL.

## Архитектура

Приложение построено по клиент-серверной архитектуре.

```text
┌──────────────────────────────┐
│          Frontend            │
│       HTML / CSS / JS        │
└──────────────┬───────────────┘
               │
          HTTP / REST API
               │
               ▼
┌──────────────────────────────┐
│       Node.js + Express      │
│           Backend            │
└──────────────┬───────────────┘
               │
        ┌──────┴─────────┐
        │                │
        ▼                ▼
   PostgreSQL         WebSocket
        ▲                │
        │                ▼
      Prisma       Игровые события
   (миграции БД)
```

REST API используется для регистрации, авторизации и работы с постоянными данными. WebSocket используется для передачи игровых событий и синхронизации состояния сессии в реальном времени.

Prisma применяется для описания структуры базы данных и управления SQL-миграциями. Существующие запросы приложения к PostgreSQL могут выполняться обычным SQL.

## Основные сущности базы данных

В базе данных WebQuiz используются следующие основные сущности:

```text
users
 ├── quizzes
 │    └── questions
 │         ├── answers
 │         └── participant_answers
 └── participants
      └── participant_answers

categories
 └── quizzes

files
 └── questions

quizzes
 ├── quiz_sessions
 │    └── participants
 │         ├── participant_answers
 │         └── quiz_results
 └── quiz_results
```

- `users` — пользователи приложения и их роли;
- `categories` — категории викторин;
- `quizzes` — викторины, созданные организаторами;
- `questions` — вопросы викторин;
- `answers` — варианты ответов на вопросы;
- `files` — метаданные загруженных файлов;
- `quiz_sessions` — игровые сессии викторин;
- `participants` — пользователи, участвующие в конкретных сессиях;
- `participant_answers` — ответы, отправленные участниками;
- `quiz_results` — результаты участников после завершения сессии.

Связи между сущностями реализованы с помощью первичных и внешних ключей PostgreSQL. Ограничения, функции и триггеры базы данных используются для поддержания целостности данных и автоматической обработки завершения игровых сессий.

# Установка и запуск

## Требования

Перед запуском необходимо установить:

- Node.js;
- npm;
- PostgreSQL;
- Git.

Проверить установку Node.js и npm:

```bash
node -v
npm -v
```

Убедитесь, что сервер PostgreSQL запущен и доступен.

---

## 1. Клонирование репозитория

```bash
git clone https://github.com/x0heart/WebQuiz.git
cd WebQuiz
```

Структура проекта:

## 2. Установка зависимостей backend

Перейдите в каталог сервера:

```bash
cd server
npm install
```

---

## 3. Настройка PostgreSQL

Создайте базу данных PostgreSQL для проекта. Например, можно использовать имя `WebQuiz`.

Подключение обычно включает следующие параметры:

```text
Название базы: WebQuiz
Пользователь: postgres
Пароль: <ваш пароль>
Хост: localhost
Порт: 5432
```

Создайте файл `.env` в каталоге `server`:

```env
DATABASE_URL="postgresql://postgres:YOUR_PASSWORD@localhost:5432/WebQuiz"
JWT_SECRET="your_secret_key"
PORT=3000
```

Замените `YOUR_PASSWORD` на пароль пользователя PostgreSQL, а `your_secret_key` — на собственный секретный ключ.

Если в пароле есть специальные символы, их необходимо корректно закодировать для URL.

> Не добавляйте `.env` в GitHub: в нём содержатся секреты и параметры подключения.

---

## 4. Настройка Prisma

В каталоге `server` после настройки `.env` выполните:

```bash
npx prisma validate
npx prisma generate
```

Проверить состояние миграций можно командой:

```bash
npx prisma migrate status
```

### Создание новой миграции

При изменении структуры базы данных обновите `prisma/schema.prisma`, затем создайте миграцию:

```bash
npx prisma migrate dev --name describe_change
```

Замените `describe_change` кратким названием изменения, например `add_quiz_description`.

> Для уже существующей базы данных не запускайте начальную миграцию повторно вручную. Начальная миграция `0_init` уже зарегистрирована в истории миграций проекта. Для развёртывания на базе, которая уже содержит данные, сначала убедитесь, что её схема соответствует миграциям.

При необходимости посмотреть содержимое базы данных:

```bash
npx prisma studio
```

---

## 5. Запуск backend

Из каталога `server` выполните команду, соответствующую скриптам в `package.json`. Если скрипт `dev` настроен:

```bash
npm run dev
```

Адрес и порт сервера определяются настройками приложения и переменной `PORT`.

# Использование приложения

## Организатор

1. Зарегистрировать аккаунт и выполнить вход.
2. Создать викторину и выбрать категорию.
3. Добавить вопросы и варианты ответов.
4. При необходимости прикрепить изображение к вопросу.
5. Настроить время на вопрос.
6. Создать игровую сессию.
7. Передать участникам код комнаты.
8. Запустить игру и следить за её ходом.
9. После завершения посмотреть результаты участников.

## Участник

1. Зарегистрировать аккаунт и выполнить вход.
2. Подключиться к игровой сессии по коду комнаты.
3. Дождаться начала игры.
4. Получать вопросы в реальном времени.
5. Отправлять ответы до истечения таймера.
6. После завершения посмотреть итоговые результаты.

## Основной сценарий работы

```text
Создание викторины организатором
              ↓
       Добавление вопросов
              ↓
      Создание игровой сессии
              ↓
          Код комнаты
              ↓
     Подключение участников
              ↓
         Запуск игры
              ↓

              ↓

              ↓
      Следующий вопрос / конец
              ↓

              ↓
      Сохранение в PostgreSQL
```

## Безопасность и целостность данных

- JWT используется для аутентификации запросов и WebSocket-подключений.
- Пароли пользователей хранятся в виде хешей.
- Правильность ответов проверяется на сервере.
- Доступ к игровой сессии проверяется с учётом роли пользователя и его участия в сессии.
- Внешние ключи и ограничения PostgreSQL помогают поддерживать целостность данных.
- Триггеры базы данных выполняют необходимые действия при изменении состояния игровой сессии и защищают сохранённые ответы от изменения или удаления.
